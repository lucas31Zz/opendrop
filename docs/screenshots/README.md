# Screenshots

Images committed here and linked from the *Screenshots* section of the
[top-level README](../../README.md). Keep the names stable: the README
points at these exact files.

| File | Subject | Theme |
|---|---|---|

| `desktop.png` | Desktop app: QR code, server address, session code, quota, folders | dark |
| `desktop-light.png` | Same window, light theme | light |
| `desktop-scroll.png` | Left column of the main window, top to bottom (the column scrolls) | dark |

| `web-settings-light.png` | Web interface, Settings panel (paired device: token, IP, dissociate) | light |

The desktop shots are full client-area captures of the app (no window
borders, no desktop background) so they stay readable at any zoom. The
`desktop-scroll.png` column shot is taken with the window temporarily
grown until the whole left column fits, then cropped back down to that
column: the Tauri UI exposes no scrollbar to automation (Chromium's
overlay scrollbars never reach the UIA tree), so there is nothing left
to scroll and stitch. The `settings-*` shots are the settings pane on
its own - an overlay inside the single window since 1.0, where it used
to be a second window. The web shots come from a headless browser
pointed at a sandboxed server.

All eleven images are regenerated by the local (gitignored) screenshot
tool, which also publishes them here under these exact names. It shoots
the release binary, and that binary must be built with Tauri's
`custom-protocol` feature: without it even a `--release` build loads
`devUrl` (http://localhost:1420) instead of the embedded assets and
shows a connection error page.

    cargo build --manifest-path desktop\src-tauri\Cargo.toml --release --features tauri/custom-protocol
    python tools\screenshots\capture.py --theme dark --publish
    python tools\screenshots\capture.py --theme light --publish
