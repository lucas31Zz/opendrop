# Tauri v1.0.0 Desktop Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Avalonia desktop app with the Tauri port as `desktop/`, close the four parity gaps the author chose (engine spawn on installed builds, update digest, Linux build + Linux auto-update, WhatsNew popup), retake the README screenshots, and rewrite every doc/CI file that still describes the .NET world — shipping v1.0.0.

**Architecture:** One restructure task renames `spike-tauri/` → `desktop/` and sets the OpenDrop identity/version 1.0.0; everything after it works under the new paths. Two new Rust modules carry the parity code (`spawn.rs` interpreter resolution, `updater.rs` tag/digest/asset logic), the React side gains a WhatsNew modal, packaging/CI are re-pointed at the Tauri binary on both platforms, then screenshots and docs follow.

**Tech Stack:** Tauri 2 (Rust, `reqwest`, new `sha2` crate), React 18 + TypeScript + Vite + Tailwind 4, Python 3.10+ engine (unchanged), Inno Setup (Windows), bash tarball (Linux), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-23-tauri-v1.0.0-desktop-design.md` (approved 2026-10-24 — the plan argues from it; executors read both).

## Global Constraints

- **No commit, tag or push without an explicit order from the author.** Every "commit" step below is a *proposal*: present the message and wait.
- Never move the author's mouse or click his windows; UIA reads/invokes only, existing ABORT guards kept. Never kill `python.exe bot.py`. Engine start/stop on his machine is his call.
- Code, comments and repo docs in **English**; UI strings FR+EN through `src/strings.ts` (WhatsNew text included).
- Version **1.0.0** must agree in: `pyproject.toml:3`, `src/opendrop/main.py:84` banner, `packaging/windows/OpenDrop.iss:14+17`, `desktop/src-tauri/tauri.conf.json`, `desktop/src-tauri/Cargo.toml` (+ lock), `desktop/package.json` (+ lock).
- The round icon is the validated art: never regenerate it from scratch; the mask stays inside `tools/make_icon.py`.
- Python suites stay green (`python -m tests.test_routes` at minimum after every engine-file touch).
- Root `.gitignore` already covers `node_modules/` and `target/` — do not re-add.
- `opensourceui/` (separate repo), `bot.py`, `docs/superpowers/` history and old CHANGELOG entries are never touched.

## Review Focus

1. **Installed build, no editable install** → engine must still start (spec B). Pinned by Task 2's installed-layout fixture test and Task 7's installtests launch-and-poll-8080 step.
2. **Digest mismatch or release without digest** → the setup must never execute unverified (spec C). Pinned by Task 3's three tests (known vector, mismatch+delete, missing digest).
3. **Pre-downloaded installer / resumed `.part`** → the "already downloaded" shortcut in `start_update_impl` (main.rs:1140) must verify too, not only a fresh download. Pinned by Task 3's explicit wiring step at both `done` gates.
4. **Linux update path** → `pkexec` cancelled, `tar` missing, and `StartupWMClass` association have no runtime proof anywhere (Windows-only author, no xvfb by decision). Pinned by Task 3's pure-function tests + error-surfacing step; the residual risk is recorded in the spec (author accepted).
5. **Screenshot retarget vs the author's live machine** → single-instance handoff would silently swallow a second launch, and UIA must not touch his cursor. Pinned by Task 8's "close the app first" step, the class-based window wait, and the UIA-only/no-mouse restatement.
